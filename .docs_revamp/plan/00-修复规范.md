## 1. 每篇必须满足

1. **读者与职责**：开头一句话说明本页给谁看、解决什么问题；开发者页说明「不负责什么」。
2. **只讲当前行为**：不叙述重构历史、评审过程、旧实现对比；历史留在 `resources/release_v0.1.rst` 或迁移说明。
3. **事实可核对**：命令、参数、默认值、路径、环境变量、extra、模型名、工具名必须能在当前代码中找到依据（给出 `file:line`）。
4. **中英语义一致**：另一语言页面同步修改；不是逐句直译，但命令、前置条件、限制、结果必须等价。
5. **不重复**：同一规则/步骤只在一处展开，其他页链接到拥有它的页面（命令行默认值归 `guides/cli`，记忆机制归 `development/memory` 等）。
6. **占位页保留**：`coming soon` / 「内容即将推出」的页不能删，改写真实状态（见 §3）。
7. **RST 规范**：一个 H1；`=`/`-`/`~` 层级；中文正文保留既有行尾 `\` 折行方式；不重排无关段落。

## 2. 状态与证据词汇（a_0 §4.4）

| 标记 | 含义 | 允许写法 |
| --- | --- | --- |
| 已验证（多次） | 多 seed / episode / 设备 | 「支持」 |
| 已验证（单次） | 一次端到端跑通 | 「在 X 上完成过一次」 |
| 仅 CPU | 契约、配置、构建通过 | 「离线检查通过」 |
| 未验证 | 有实现，无运行证据 | 「尚未验证」 |
| 实验性 | 接口可能变化 | 「Experimental」 |

任何「支持 / 可用 / 兼容」都要能对上一行；对不上就降级表述。

## 3. 验证状态段

仿真页与真实机器人页在「概览」后、「安装」前增加：

```rst
验证状态
--------

- 已验证（多次）：<环境/硬件>，<日期>，commit <hash>，<seed/任务/配置范围>
- 仅 CPU：<检查内容>
- 未验证：<有实现但无运行证据的部分>
```

只写有证据的内容；没有证据就写「尚未验证」并说明原因。已有发布数据的页面引用
`resources/release_v0.1.rst` 或 leaderboard，不复制数字。

## 4. 事实核查方法

- 参数：`grep -rn '"--flag"' --include='*.py' .`（注意共享注册函数 `add_am_args`、`add_cuda_device_arg`）
- 默认值：读 `add_argument(..., default=...)` 与运行配置解析
- 路径：文档中的 `robots/...`、`rpent/...` 必须存在；示例路径（`/path/to/...`、`myrobot`）除外
- 环境变量：`os.getenv` / `os.environ`；动态拼接的（如 `VPP2_MODEL_PATH`）人工确认
- extra：`pyproject.toml` 的 `[project.optional-dependencies]`
- 命令：`rpent`、`rpent-memory`、`rpent-check-llm`、`rpent-flywheel` 以 `[project.scripts]` 为准

## 5. 禁止

- 改代码、改测试、改 `pyproject.toml`（发现代码问题只报告）
- 删除占位页、排行榜数据、实验复现数据、图表或链接
- 用 `git checkout`/`git restore` 撤销工作区已有改动
- 任何 `git add` / `commit` / `push`
- 无证据地把「未验证」写成「支持」
