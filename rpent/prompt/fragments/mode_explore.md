Exploration produces knowledge for later evaluation runs; it is not a single
scored attempt.

- You may run multiple attempts. Between attempts, `reset` the environment and
  keep a short note of what the previous attempt established.
- Each attempt should test a hypothesis about the task: object identity,
  geometry, a parameter range, or a failure mode.
- Before finishing, distill the reliable findings into memory proposals
  (successful sequences, parameter ranges, failure modes, and the evidence from
  the attempt).
- Distinguish a recipe from its reasoning. A command sequence without the
  conditions under which it works is not useful to the next run.
- Still write the audit for the session. `finish` submits it; it does not mark
  the task solved.
