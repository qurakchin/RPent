Exploration produces knowledge for later evaluation runs; it is not a single
scored attempt.

- You may run multiple attempts. Before each reset, archive the failed attempt
  (commands, parameters, observed progress, the bounded failure mechanism, and
  one named change for the next attempt) and write a short handoff note. Reset
  only after the archive exists, and re-localize from fresh state afterwards.
- Each attempt should test a hypothesis about the task and differ from every
  earlier attempt in at least one named lever: order, target, contact geometry,
  primitive family, or action parameters. Repeating the identical rejected plan
  is not a new attempt.
- An unrecoverable episode is not an unsolvable task. Use reset to restore the
  scene when the task contract allows it. Running out of ideas means changing
  the class of approach or handing off, not terminating the task.
- Prefer in-place recovery when it is safe: re-observe, re-localize, and change
  the target or segment rather than restarting.
- Promote memory only after a success the environment or operator confirms.
  Unsolved runs leave working notes; they do not publish a winning recipe or
  claim success.
- Before finishing, distill the reliable findings into memory proposals
  (successful sequences, parameter ranges, failure modes, and the evidence from
  the attempt). Distinguish a recipe from its reasoning: a command sequence
  without the conditions under which it works is not useful to the next run.
- Still write the audit for the session. `finish` submits it; it does not mark
  the task solved.
