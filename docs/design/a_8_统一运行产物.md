# a_8 统一运行产物
> 状态：草案｜基线 `01e9cb3`｜最后更新 2026-11-13

> 每次运行一个 manifest，transcript 作为单个对象写入，工具调用、step 和 RPC 可以按 ID 关联查询。
>
> 前置阅读：[a_global](a_global.md) R9。

## 1. 问题背景

step 级产物已经做得很扎实：`EnvState` 用 `states.json` 作为 manifest，原子替换写入（`rpent/session/base.py:142-154`）；`record_step` 出错时会回滚（`:325-383`）；产物名做了路径穿越校验；`write_json_atomic` 也已经有现成实现（`rpent/evaluation/result.py:50-64`）。

问题集中在 run 级：

1. **transcript 追加写。** 代码用 `open(transcript_path, "a")`（`rpent/cli/main.py:716-728`）。在同一个目录重跑一次，文件里就会有两个 JSON 对象，既不是合法 JSON，也分不清哪个属于哪次运行。
2. **没有 run manifest。** task、seed、model、planner、prompt、工具 schema、环境 revision、checkpoint、git commit 分散在 CLI 参数、transcript 和日志里。
3. **`result.json` 由各切片自行决定写什么。** 没有 `RunFinalizationContext`（a_7），没有执行状态（a_6），也没有 prompt 和工具 schema 的指纹。
4. **事件只服务 Dashboard。** `DashboardEventSink`（`rpent/dashboard/events.py:21-72`）只是 UI 投影，没有 Dashboard 时根本不产生事件，事后无法回放工具调用序列。
5. **没有关联 ID。** `ToolResult`、`StepRecord` 和 RPC 之间没有共享 ID，三份记录 join 不起来。

## 2. 根因

1. **run 级产物没有统一入口。** step 级由 `EnvState` 统一管理，run 级却由各切片的 `finalize_run` 各写一套，字段随切片变化。
2. **写入语义不统一。** 有的文件原子替换，有的追加，混放在同一个目录里。
3. **事件系统只有一个消费者。** 审计日志和 UI 投影本应共享同一个事件源，现在只有 UI 投影。

## 3. 优秀参考、原则与结构

| URA 做法 | 说明 | 借鉴 |
|---|---|---|
| run record | `build_run_result` 把配置、任务、episode 身份、outcome、stats、产物状态合成一条记录（`artifacts/run.py:14-86`） | 字段集合 |
| 原子写 + 相对路径 | `write_result_json`（`run.py:104-113`） | 产物目录可以整体迁移 |
| 单一事件总线 | `EventBus` 统一分配 `event_seq`；JSONL、console、TUI、Web 都是订阅者；订阅者出错只熔断自己，不影响控制路径 | **核心**：Dashboard 和 JSONL 共用一个事件源 |
| 大产物外部化 | 图片存成文件，事件中只放引用 | 照搬 |

**不照搬**：telemetry 框架（Tracer / span / metric）。RPent 现阶段用 `elapsed_s` 加事件时间戳就够用了。

**原则**：

- 一次运行对应一个 manifest；
- 所有 JSON 都原子写，禁止追加；
- 每个事件都带上关联 ID；
- 产物写入失败不影响物理执行。

## 4. 目标设计

### 4.1 目录布局

```
<output_dir>/
  run.json              # RunManifest
  result.json           # RunFinalizationContext（a_7）；旧字段保留一个 release
  transcript.json       # 单个对象，原子写
  effective_prompt.md   # a_2
  prompt_sources.json   # a_2
  tools.json            # 模型实际看到的工具 schema（a_3）
  states.json           # 现有的 step manifest，只增加字段
  events.jsonl          # 事件流
  run.log
  images/ videos/ attempts/ sessions/   # 现有目录，不变
```

### 4.2 `RunManifest`

```python
@dataclass(frozen=True)
class RunManifest:
    layout_version: int
    run_id: str
    episode_ids: list[str]     # 本次运行内的 episode（explore 每个 attempt 一个，a_global 2.2）
    robot: str
    task: dict                 # suite / task / seed / instruction
    planner: str
    model: str | None
    reasoning_effort: str
    policy_mode: str           # tool | code（a_4）
    run_mode: str              # evaluate | explore
    interactive: bool          # 是否 Dashboard
    truth_visibility: str      # hidden | visible（a_7）
    capabilities: dict         # a_3 的能力快照
    profile: str | None        # a_1 的环境配方
    env_fingerprint: str | None  # a_1 安装指纹的 sha256
    success_criteria: dict     # a_7
    prompt_sha256: str
    tools_sha256: str
    memory_revision: str | None
    env_revision: str | None
    checkpoint_sha256: str | None
    git_commit: str | None
    started_at: str
    finished_at: str | None
    storage_errors: list[str]
```

- 分三次原子写：启动时写入身份、任务、planner、模型、运行轴、安装指纹和 git；工具与 prompt 装配完成后补写 `capabilities`、`tools_sha256`、`prompt_sha256`；结束时补写 `finished_at`、`episode_ids` 和 `storage_errors`。第二次写入之前不发出任何写请求；
- `profile` 和 `env_fingerprint` 来自 a_1 的 `<venv>/rpent-install.json`；没有安装指纹的运行（例如直接用 `pip install` 的环境）写 `null`，并在 `storage_errors` 或日志里说明；
- 敏感信息（key、token、外部绝对路径）脱敏。

### 4.3 transcript 与 result

- transcript 改为单个对象，原子写入 `transcript.json`，内容包括 `run_id`、`prompt_sha256`、`tools_sha256`、`stats`、`messages`；
- 旧的 `transcript_{recipe_tag}.json` 不再追加写；
- **一个输出目录只对应一次运行**：目录里已有 `run.json` 时，CLI 在启动前报错并提示换一个目录，不覆盖、不归档。Flash recipe 这类跨运行复用的文件不在此列，仍按现有路径读写；
- 写入顺序：transcript → result → 更新 `run.json`。任何一步失败都记入 `storage_errors`，不留下写了一半的文件。

### 4.4 单一事件源

```python
# rpent/artifacts/events.py
class EventSink(Protocol):
    def emit(self, event: dict) -> None: ...

class EventBus:                      # 分配 seq，补 ts / run_id / episode_id，然后分发
    def subscribe(self, sink: EventSink) -> None: ...
    def emit(self, kind: str, **fields) -> None: ...

# 订阅者：JsonlEventSink（总是开启）、DashboardEventSink（interactive 时开启，沿用 rpent/dashboard/events.py）
```

- 现有 `DashboardEventSink` 改为实现 `EventSink` 的一个订阅者，不再是唯一的事件源；
- 事件类型保持最小集：

  | 事件 | 关键字段 |
  |---|---|
  | `run_started` / `run_finished` | `run_id`，`outcome` |
  | `tool_call` / `tool_result` | `tool_call_id`、`tool_name`，四层结果字段（a_3） |
  | `step_recorded` | `step_idx`、`tool_call_id`、`request_id`、`state_version` |
  | `env_request` | `request_id`、`sequence`、`execution_status`、`duration_ms`；未确认的请求以 `unknown` 记录，供人工确认（a_6 4.2） |
  | `operator_action` | `request_id`、`action`、`verdict`（真机） |

- 订阅者写入失败只记一次告警，然后熔断，不阻塞工具执行；
- 代码模式下，每个 cell 内的工具调用照常发出 `tool_call`，事件中额外带上 `cell_id`（a_4）。

### 4.5 StepRecord 关联字段

`StepRecord` 新增四个可选字段：`tool_call_id`、`request_id`、`tool_name`、`execution_status`。读旧文件时缺失的字段按 `None` 处理，`states.json` 保持向后兼容。

## 5. 目标与非目标

**目标**

- 统一的目录布局和 manifest；
- 重跑不再污染已有产物；
- 只凭产物目录就能回答三个问题：跑了什么、模型看到了什么、结果是否可以接受；
- 工具调用、step 和环境请求能按 ID join 起来。

**非目标**

- 不引入 OpenTelemetry 或 Prometheus，也不做 span/metric 框架；
- 不改变 `states.json` 的现有语义，不把图像或视频塞进 JSON，不做云端上传；
- 不迁移历史运行的产物，新布局从 `layout_version=1` 开始；
- 暂时不做 `rpent reproduce` 命令：manifest 已经足以人工复现，等出现真实需求再加。

## 6. 如何实施

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P1 manifest 与原子写** | 写出 `run.json`；transcript 改为单个对象；`result.json` 由 `RunFinalizationContext` 驱动 | 每个 run 目录都有 manifest；在已有 `run.json` 的目录重跑会在启动前被拒绝；写入失败不留下半个文件 |
| **P2 事件总线** | `EventBus`、`EventSink`、`JsonlEventSink`；`DashboardEventSink` 改为订阅者 | 不开 Dashboard 时事件也完整；并发写入不会交错；Dashboard 行为不变 |
| **P3 关联 ID** | `tool_call_id` 和 `request_id` 贯穿工具、step 和 RPC | 一次工具调用能 join 到对应的 step 和 env request；旧的 `states.json` 仍可读取 |

P1 可以最先做，不依赖其他主题。P3 依赖 a_6 的 `request_id`。

## 7. 验收指标

| 指标 | 基线 | 目标 |
|---|---|---|
| run manifest 覆盖率 | 0 | 100% |
| 重跑产生非法 JSON 或覆盖旧产物 | 存在 | 0 |
| 事件源 | 只有 Dashboard | 一个总线，多个订阅者 |
| 关联 ID 覆盖率 | 0 | 100% |
| manifest 覆盖的复现要素（seed / model / prompt / tools / memory / checkpoint / git） | 分散在各处 | 100% |

## 8. 风险

| 风险 | 对策 |
|---|---|
| 写放大 | 按行缓冲、定期 flush；事件里只放引用，不放图像 |
| 敏感信息外泄 | manifest 脱敏；配置输出走同一个脱敏函数 |
| 兼容性 | 只新增字段，不删字段；旧 transcript 和 `states.json` 仍可读取 |
| Dashboard 改成订阅者后出现回归 | 迁移前后对比 Dashboard 的事件序列，parity 测试覆盖 |
| 把「复现」误当成「重放」 | 文档中区分清楚：manifest 保证配置可以复现，不保证物理结果一致；Flash 才是重放 |
