# RPent 改造全局规范
> 状态：草案｜基线 `b4d8459`｜最后更新 2026-11-13

本文件是改造系列的共同底座，包含术语、分层职责、规则、开关、验收口径和文档地图。各主题文档只引用这里的条目，不再重复。

- **基线**：RPent `main` `b4d8459`；URA（uni-robot-agent）`852518e`；代码策略部分以 RLinf/RPent PR #340（open）为参照。
- **基线规模**（口径见第 5 节）：`rpent/` 18.1k 行 / 83 个文件，`robots/` 35.7k 行 / 125 个文件，测试 97 个。

## 1. 改造要解决什么

一句话：**RPent 以「机器人」为封装单位，于是每接一个机器人都要把整条栈重铺一遍；改造要把封装单位换成「能力」**。

| 症状 | 证据（基线） | 主题文档 |
|---|---|---|
| 切片太大，接入成本高 | 单切片 3.5k–7.4k 行；URA 同一个 RoboTwin 只有 234 行 | a_5 |
| 通用动作复制多份 | `move_to` 在 6 个文件定义，`view_env_state` 7 个，`rotate_wrist` 5 个，`back_project` 4 个 | a_3 |
| 工具无法单独评估 | 改阈值、点选或拟合只能看整段 episode 是否成功；`segment` / `back_project` 在 4–5 个切片各有实现，没有共同基线 | a_3、a_9 |
| 组件依赖和安装没有边界 | 14 个 extra、7 个继承、15 对手写冲突；`toolkits/` 被排除在打包之外；安装说明分散在 16 个页面 | a_1 |
| 物理动作可能执行两次 | RPC 失败无法区分「没执行」与「执行了但回执丢了」 | a_6 |
| 评测真值泄露给模型 | `pi0_pick` 返回 `terminated`，`get_env_state` 提示「call finish with success」 | a_7 |
| prompt 按切片复制 | 切片 prompt 合计约 3.0k 行，记忆协议每个切片写一遍 | a_2 |
| 运行不可复现 | transcript 追加写，没有 run manifest | a_8 |
| 设计会慢慢退化 | 测试按模块组织，没有契约测试和架构检查 | a_9 |
| 新调用模式继续按切片复制 | PR #340 的代码模式给 7 个切片各加一份 prompt，共 794 行 | a_4 |

## 2. 术语

| 术语 | 含义 |
|---|---|
| **切片** | `robots/<name>/` 目录，一个机器人或仿真的实现 |
| **契约** | 跨进程、跨模块的稳定数据类型及其语义，如 `get_env_meta()` 的返回 dict、`ToolResult.execution_status` |
| **adapter** | 切片里把原生仿真或真机翻译成契约的那一层 |
| **能力声明** | 环境能力的只读快照（臂、相机、深度、标定、分割、策略后端等），决定暴露哪些工具和参数 |
| **工具族** | 按能力组织的一组共享工具：Scene / Motion / Memory / File，对应 `SceneTools` / `MotionTools` / `MemoryTools` / `CommonTools`；它是装配与发现的分组，不拥有实现，也不承担评估 |
| **工具包** | `toolkits/<name>/`，一个共享能力的实现、输入契约、内部算法和评估语料的整体；对外暴露少量工具，对内保留 ground、segment、back-project 这类原语。工具上下文（`EnvState` 的步历史、历史帧、产物引用）由 Toolkit 注入，工具不自己翻目录 |
| **组件** | 可安装单元：`robots/<name>/`、`toolkits/<name>/` 或 `rpent/robots/components/<name>/`；目录内的 `component.toml` 声明直接依赖、Python/平台范围、冲突、放置方式和导入探针（a_1） |
| **环境配方** | `envs/<profile>.toml`，把若干组件按放置方式组合成一个可安装环境；受支持目标只通过具名配方安装（a_1） |
| **安装指纹** | 安装成功后写在 venv 里的 `rpent-install.json`，记录配方、组件清单 hash、依赖锁、Python/平台和冻结 hash；`run.json` 引用它（a_1、a_8） |
| **VLA/WAM client binding** | 切片为某个 VLA/WAM 技能提供的编码、解码和成功判据，由 Motion 族里的 `vla_act` runner 调用 |
| **回执** | 服务端对一条写请求的执行结论：执行了没有、执行到哪一步 |
| **对账** | 按 `request_id` 只读查询回执；**永不重放动作** |
| **不确定态** | 可能执行了但无法确认；锁存后拒绝所有写操作 |
| **真值** | 环境、评测器或操作员给出的任务成功判定 |
| **调用模式** | 模型使用工具的方式：JSON tool call，或代码策略（在 Python cell 里调用 `robo.<tool>()`）。两种模式使用同一份工具声明 |
| **片段** | 可复用的 prompt 段落，带来源 |

## 3. 分层职责

```
Planner（claude_code / codex / api / flash）
  │  调用模式：tool call │ code policy（同一工具声明）
Prompt 拼装 ── 片段库 + 工具族贡献 + 领域片段
工具与工具上下文 ┬─ Toolkit ───── 调度（readonly 并发 / 写者优先）+ ToolResult 四层 + 工具上下文（EnvState 步历史 / 历史帧）
                 ├─ 工具族 ────── Scene / Motion(+vla_act) / Memory / File（装配分组）
                 ├─ 工具包 ────── toolkits/<name>/：实现 · 输入契约 · 独立评估
                 └─ Episode 会话 ── 不确定态锁存 · RunFinalizationContext
  │  语义命令（pose / joints / native chunk）
BaseEnvClient ─ 身份 · 回执 · 自动对账          ┐
  │  RPC（HTTP JSON / socket）                  ├ 核心，全仓一份
BaseEnvFacade ─ 路由 · 生命周期 · ReceiptLedger ┘
  │
adapter ───── 原生翻译（约 8 个方法）          ┐
VLA/WAM client binding · 能力声明 · 领域片段   ├ 切片
原生仿真 / 真机 / 运营与安全逻辑               ┘

安装边界 ── component.toml（组件）→ envs/<profile>.toml（配方）→ rpent-install.json（指纹）
```

**判断代码归属**：

- 对两个以上机器人都成立的逻辑，不属于切片；
- 只对某一个原生环境成立的逻辑，属于切片，并且要在注释里说明它是**原生差异**，不是框架缺陷。

## 4. 规则

所有规则写进 `AGENTS.md` 和 review checklist；R1、R2、R8 以及 R11 的包边界由 `check_layout` 机器检查（a_9），评估质量由评审核对；R12 的组件清单和环境配方由 `rpent-env check` 检查（a_1）。

| 编号 | 规则 | 要点 |
|---|---|---|
| **R1** | 一种能力只实现一份 | 通用动作、感知、环境 client/facade、记忆协议、输出格式全仓各一份；要新增第二份，先说明为什么不能复用 |
| **R2** | 切片只做翻译 | 切片负责：原生 → 契约、能力声明、技能判据、领域知识。切片不负责：模型可见的通用工具、调度、通用 prompt、产物布局、评测口径 |
| **R3** | 物理写操作可识别 | 每条写请求带 `episode_id`、`request_id` 和单调递增的 `sequence`；重复请求返回已有回执；丢失回执不等于失败，也不允许重放 |
| **R4** | 区分未执行与不确定 | 工具结果显式区分四件事：调用是否有效、动作是否执行、执行是否确定、领域结果 |
| **R5** | 评测模式不暴露真值 | 模型可以知道 episode 是否结束，但不知道是否成功；探索模式可以暴露真值，但必须标记 |
| **R6** | 判据属于配置 | 成功阈值放在机器人或 benchmark 配置里，模型不能通过工具参数放宽 |
| **R7** | 共享代码至少两个使用方 | 新增核心模块或契约字段时，PR 里要写明两个以上使用方；否则留在切片。**没有调用点的字段、开关和扩展点不进核心** |
| **R8** | 核心不出现机器人名 | 平台差异通过能力声明和切片配置表达 |
| **R9** | 运行可复现 | 每次运行都写出 `run.json`、`effective_prompt.md`、`tools.json`、`result.json`；缺任何一个，该运行不进评测统计 |
| **R10** | 迁移期旧路径可用 | 旧路径保留到「试点切片完成，且又有一个切片通过 parity」为止；同一个 release 内不做协议的破坏性变更 |
| **R11** | 共享工具自带评估 | 每个共享工具都要有独立于 episode 的验证入口（契约测试或评估语料）；有模型参与的感知工具必须以工具包为单位提供固定语料、独立参考和可重放报告；改动附同一语料的前后对比，badcase 进入下一语料版本或回归测试 |
| **R12** | 依赖随组件声明 | 每个 robot、toolkit、共享能力自带 `component.toml`；根 `pyproject.toml` 只保留核心依赖，机器人/模型依赖不得直接写进根清单；组件冲突显式声明并做对称检查；安装只通过 `rpent-env` 和具名配方，不要求用户手工组合 extra |

## 5. 通用口径

### 5.1 代码行数

- 只统计 `.py` 文件，不含 `tests/` 和 `__init__.py`；`.md` 片段单独统计；`component.toml` 和 `envs/` 是 TOML，不计入 Python 行数；
- `toolkits/` 单独统计，实现与 `evaluation/` 分开报告；
- 切片行数分成两部分报告：
  - **接入部分**：adapter、VLA/WAM client binding、配置与能力声明、领域 prompt、原生特有工具；
  - **差异化功能**：Flash、记忆策略 hook、benchmark 评测脚本、真机运营与安全（operator、硬件租约、伺服、恢复、标定）；
- 「≤1.2k 行」这类目标只约束**接入部分**。差异化功能是 RPent 的核心竞争力，不设压缩目标，只要求不重复实现。

### 5.2 测试分层

不新增顶层测试目录，契约测试和故障注入放进 `unit_tests/`，沿用现有 CI：

| 层 | 位置 | 依赖 | 何时运行 |
|---|---|---|---|
| 单元 + 契约 | `tests/unit_tests/contracts/` | fake 实现，CPU | 每个 PR |
| 故障注入 | `tests/unit_tests/fault_injection/` | `FakeEnvServer`、`FakeRpcTransport` | 每个 PR |
| Parity | `tests/parity/` | scripted planner，不调 LLM | 每个迁移 PR |
| 工具评估 | `toolkits/<name>/evaluation/` | 冻结观测、点选与 mask，独立参考 | 工具改动与 nightly |
| 安装 | `envs/` 与 `component.toml` | 清单、闭包与冲突检查用 CPU；fresh venv 安装用真实依赖 | 每个 PR / nightly |
| 端到端 | `tests/e2e_tests/`（现有） | 真实仿真 / GPU | nightly 与 release |

离线测试（契约、故障注入、parity、工具评估、安装检查）不能证明真机可用。真机只验证可判定的部分：回执、锁存、门控、配置校验，并且结果单独记录。

### 5.3 开关

全系列**只有一个迁移开关**：

| 开关 | 取值 | 作用域 | 生命周期 |
|---|---|---|---|
| `env_contract` | `legacy \| v2` | 按切片 | 所有切片迁移完成后删除 |

其余改动都原地替换，用 parity 测试和 git revert 兜底。a_1 的 extras 兼容别名不是迁移开关，而是从组件清单生成的元数据，保留一个 release 后删除。另有两个属于运行配置、不属于迁移开关的选项：

- 真值可见性：跟随运行模式，评测模式隐藏，探索模式可见；
- 调用模式：`--policy-mode tool|code`。
