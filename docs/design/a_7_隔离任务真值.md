# a_7 隔离任务真值
> 状态：草案｜基线 `b4d8459`｜最后更新 2026-11-13

> 把「模型说成功」「环境判定成功」「进程正常结束」三件事分开；评测模式下，真值不再进入模型上下文。
>
> 前置阅读：[a_global](a_global.md) R5/R6；[a_6](a_6_建立执行回执语义.md) 的不确定态。

## 1. 问题背景

RPent 现在有三个「成功」来源，但没有分开：

1. **模型说成功**：调用 `finish(status="success")` 后返回 `_finish`，planner 据此停止（`rpent/tools/common.py:88-96`）；
2. **环境判定成功**：各 toolkit 的 `solved()`，例如 LIBERO 用的是累计的 `record.terminated`（`robots/libero/toolkit.py:209`）；
3. **进程正常结束**：CLI 退出码只有一种判断，`1 if agent_error else 0`（`rpent/cli/main.py:787`）。

由此带来四个具体问题。

**真值泄露给模型**
- `pi0_pick` 直接返回 `terminated`，以及由它推导出来的 `success`（`robots/libero/tools.py:294-324`）。
- `get_env_state` 在 `terminated` 为真时提示模型 `next_action="Call finish with status='success'"`（`robots/libero/toolkit.py:229-234`）。
- PR #340 的 RoboTwin 代码模式 prompt 甚至明确写着「只有原生 `eval_success` 能证明任务成功」，并教模型去读这个字段。

模型照抄真值，评测就失去了意义。LIBERO 中 `terminated` 由任务成功触发，等同于把 verifier 的结果交给了模型。

**判据可以被放宽**
- `pi0_pick(..., lift_thresh=0.05, gripper_closed_thresh=0.06, ...)` 把成功阈值做成了工具参数，planner 可以自己放宽到「必然成功」。

**guard 只有个别切片有**
- 只有 LIBERO 有 `_guarded_finish`（探索模式）和 `_wam_finish`。其他切片里，「模型自报成功」这条路完全没有拦截。

**结果无法判定**
- `RunFinalizationContext` 只有 `environment_success`、`agent_error`、`finish_result` 三个字段，没有「是否可接受」和「是否可重试」（`rpent/evaluation/result.py:27-44`）。外部 runner 无法判断要不要重跑。

## 2. 根因

1. **没有一个结果契约。** 「agent 结束」和「环境判定」是两个零散的信号，没有任何地方规定它们怎么组合、哪些字段互斥、什么时候算不可判定。
2. **判据放在了工具参数里。** 工具参数应该回答「这次怎么做」，不应该回答「什么算成功」。
3. **真值没有隔离。** 「episode 结束了没有」和「任务成功了没有」混在同一个 `terminated` 字段里。
4. **退出码只表达崩溃。** 任务失败、agent 崩溃、基础设施故障三种情况分不开。

## 3. 优秀参考、原则与结构

| URA 做法 | 说明 | RPent 借鉴 |
|---|---|---|
| `finish` 只返回 `{"submitted": true}` | 不把判定告诉 agent | **核心**：评测模式下照此处理 |
| `call_ok` | 工具结果中的「调用有效」，与任务成功区分开 | 已在 a_3 落地 |
| `EpisodeOutcome` | `accepted` 与 `retryable` 互斥，基础设施失败不计入分母 | 互斥约束写进 `__post_init__` |
| 结果记录 | `task_success`、`accepted`、`retryable`、`failure_category`、`agent_finished`、`stop_reason` | 字段集合 |
| 退出码 75 | 表示可重试，与外部 runner 约定 | 照搬 |

**URA 自己的漏洞，RPent 不重复**：RoboDojo 适配器在步数上限时，`terminated` 实际等价于 `env.success`，而 observation profile 会把这个字段透传给模型。RPent 在契约层直接只给出 `episode_over`（a_5），从源头上堵住这条路径。

**原则**：

- `environment_success` 只能来自环境、评测器或操作员；
- 模型自报只影响 `finish_result`；
- 模型可以知道 episode 结束了，但不知道是否成功；
- 判据由配置决定。

## 4. 目标设计

### 4.1 `RunFinalizationContext`：`rpent/evaluation/result.py`

```python
@dataclass(frozen=True)
class RunFinalizationContext:
    # 现有字段保持不变：environment_success / agent_error / finish_result / ...
    # 新增字段：
    accepted: bool = False                # 结果可以被评测接受（任务失败也可以是 accepted）
    retryable: bool = False               # 由基础设施故障或不确定态导致不可判定，允许重跑
    failure_category: str | None = None   # agent_error | task_failure | execution_uncertain | timeout | config_error
    stop_reason: str | None = None        # finish | max_turns | operator_abort | timeout | error

    def __post_init__(self):
        if self.retryable and self.accepted:
            raise ValueError("retryable and accepted are mutually exclusive")
```

直接扩展 `RunFinalizationContext`；旧字段保留一个 release。

### 4.2 finish 策略统一到 Toolkit 基类

| 模式 | `solved()` | 模型声明 | 行为 |
|---|---|---|---|
| evaluate | 任意 | 任意 | 接受，只返回 `{"submitted": true}`；`environment_success` 只写入结果文件 |
| evaluate | 不确定态已锁存 | 任意 | 接受；结果标记为 `retryable`，`failure_category=execution_uncertain` |
| explore | False，且还有剩余 attempts | success | 拒绝，提示先 `reset` 再试（LIBERO 现有行为上移到基类） |
| explore | 其他情况 | 任意 | 接受，返回值中带 `ground_truth` 标记 |

切片不再实现自己的 guard，LIBERO 的 `_guarded_finish` 和 `_wam_finish` 改为配置项。evaluate 模式不再「拒绝未解出时的 success 声明」，因为拒绝本身也会泄露真值。

### 4.3 判据外置

```python
# 每个切片在 config.py 中给出 success_criteria dict（沿用 RunConfig）：
success_criteria = {
    "lift_thresh": 0.05,
    "gripper_closed_thresh": 0.06,
    "descent_thresh": 0.03,
}
```

- VLA/WAM client 的 `judge` 从配置读取阈值（a_3），工具参数中只保留 `max_chunks` 之类的预算参数；
- 判据配置写入 `run.json`（a_8）；
- 技能判据只代表**子目标**结果，不代表任务成功，在 prompt 中说明清楚（a_2）。

### 4.4 真值可见性

可见性跟随运行模式，是运行配置，不是迁移开关。

| 模式 | 模型能看到 | 模型看不到 |
|---|---|---|
| evaluate（默认 hidden） | `episode_over`、技能的诊断量（如抬升高度、夹爪开度）、图像 | `terminated`、`truncated`、`environment_success`、由真值推导出的 `success`、`eval_success`、「call finish with success」这类提示 |
| explore（visible） | 以上全部，并带 `ground_truth=true` 标记 | — |

- 过滤在框架层完成：契约本身只提供 `episode_over`，真值只经 `adapter.finish()` 写入产物；
- 真值仍然写入 `StepRecord.extras`、`states.json` 和 `result.json`；Dashboard 给操作员展示真值，与模型可见的内容分开；
- 为口径校准保留一个显式选项 `--truth-visibility visible`，只用于 evaluate 模式下的对照实验。

### 4.5 退出码

| 码 | 含义 |
|---|---|
| 0 | 运行完成，结果 `accepted`（任务成功或失败都算） |
| 1 | 配置错误或 agent 崩溃 |
| 75 | `retryable`：不确定态、超时、基础设施故障 |

任务是否成功看 `result.json` 里的 `environment_success`，不通过退出码表达。

## 5. 目标与非目标

**目标**

- 三种成功彻底分开：`call_ok`（a_3）、`finish_result`、`environment_success`；
- 评测模式的真值泄露为 0，代码模式也一样（a_4）；
- finish 策略只在基类实现一份，判据外置到配置；
- `result.json` 和退出码能让外部 runner 判断是否需要重跑；
- 用对照实验量化口径修正对成功率的影响。

**非目标**

- 不修改各 benchmark 的官方 evaluator；
- 不强制所有机器人实现 `solved()`，没有真值时 `environment_success=None`，不伪造 `False`；
- 不删除 `finish`，也不改探索模式的 attempts 和 reset 流程。

## 6. 如何实施

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P1 RunFinalizationContext 与退出码** | 扩展结果契约，CLI 构造结果，退出码 0 / 1 / 75 | 成功、任务失败、崩溃、uncertain 四种场景都有测试；旧的 `finalize_run` 仍可用 |
| **P2 finish 策略统一** | 基类实现策略表，切片中的 guard 改为配置 | 切片里自有 guard 的数量为 0；探索模式行为不变 |
| **P3 判据外置** | 切片 `success_criteria` dict，工具移除阈值参数 | 工具 schema 中不再出现成功阈值；固定 seed 下行为与旧默认值一致 |
| **P4 真值隔离与口径校准** | evaluate 默认 hidden；用固定 seed 对比 visible 与 hidden | 评测模式的工具结果快照中不含真值字段；校准报告合入文档，排行榜注明口径 |

P4 会改变模型行为，必须和校准实验一起做，否则无法区分「口径修正」和「模型变差」。

## 7. 验收指标

| 指标 | 基线 | 目标 |
|---|---|---|
| 评测模式下模型可见的真值字段 | 存在（LIBERO 原语、`get_env_state`、#340 代码模式 prompt） | 0 |
| 工具参数中的成功阈值 | 至少 4 个 | 0 |
| finish guard 实现份数 | 2（LIBERO） | 1（基类） |
| 退出码可区分的场景 | 2 种 | 3 种 |
| visible 与 hidden 的成功率差 | 未测量 | 有校准报告 |

## 8. 风险

| 风险 | 对策 |
|---|---|
| 评测数字下降，历史结果不可比 | 校准报告给出新旧口径的差值；排行榜注明口径；旧字段保留一个 release |
| 模型拿不到真值后反复尝试或过早 finish | 提供 `episode_over`、诊断量和图像作为替代信号；prompt 中说明「子目标判据不等于任务成功」 |
| 没有真值的机器人 | 设 `environment_success=None`，标记 `no_ground_truth`，单独统计 |
| 真机判定带主观性 | operator verdict 记录来源、时间和操作员，并且不进入模型上下文 |
| 依赖 a_6 | a_6 落地之前，`retryable` 只来自超时和崩溃 |
